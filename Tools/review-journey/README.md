# 客厅评审引导与坐姿体验

当前 `SceneNew` 已接入完整的一轮评审。打开场景进入 Play，点击 `START REVIEW`。现有基础操作教程可通过 `CONTROLS` 或原有 HELP 再次打开。

右上角 `x` 和 `FREE EXPLORE` 会关闭任务卡、路线及操作高亮，并暂停评审进度。腕部菜单现在是 `PAUSE / HELP / GUIDE / END REVIEW / GAPS`。点击 `GUIDE` 可继续原评审；`HELP` 保留基础操作教程。`END REVIEW` 保存本轮结果并进入双列表总结，结束后该按钮变成 `RESULTS`，关闭总结后可再次打开。

点位评价卡提示用侧面 `GRIP` 指向物体添加分类和原因。分类沿用 `inappropriate size`、`too cramped`、`strange layout`；提交前须选分类并填写原因，最多 500 字符。提交成功后返回原点位，保存失败时保留原输入。

总结卡的 `POINT REVIEWS` 列出全部六个评价点，未回答项显示 `UNRATED`。`OBJECT NOTES` 按物体分组列出分类和原因；同一物体的多条标注分别保留，可点击条目并翻页查看完整内容。`RETURN TO REVIEW` 保留数据继续补充，`NEW REVIEW` 新建一轮并保留上一轮文件。坐姿下总结卡内提供 `STAND UP`；拿着遥控器或处于坐站转场时不能结束。有未提交标注时，结束入口会在原编辑卡中提供 `SAVE & END` 与 `KEEP EDITING`，不会静默丢弃草稿。

## 完整线路

| 步骤 | 站位 X / Z（米） | 观察或操作 | 完成条件 |
|---|---|---|---|
| 1 入口整体观察 | -2.45 / -1.55 | 分别观察沙发与电视墙，判断空间是否容易理解 | 到达脚印圈，朝两个眼睛图标观察，然后选择评价 |
| 2 展示柜前方 | -2.85 / 1.35 | 沿西侧通道绕过扶椅，观察储物正面和前方空间 | 观察展示柜后选择评价 |
| 3 书柜与通行 | 1.65 / 1.40 | 经北侧通路，观察书柜及旁边扶椅的关系 | 观察两个目标后选择评价 |
| 4 电视侧向视线 | -0.95 / 1.30 | 从侧面判断电视可见性，之后与坐姿正面视角比较 | 观察电视后选择评价 |
| 5 沙发与茶几 | -1.05 / 0.00 | 从侧面观察桌面高度、沙发前缘和二者间距 | 观察两个目标后选择评价 |
| 6 进入坐姿 | -0.95 / -0.06 | 用扳机点击沙发旁的座椅图标 | 坐姿切换完成 |
| 7 坐姿观察 | 眼位 0 / 1.21 / -0.55 | 正面看电视，再看茶几，判断观看与日常使用关系 | 观察两个目标后选择评价 |
| 8 取放遥控器 | 桌面前缘 -0.20 / 0.445 / 0.14 | 手靠近后出现白色手形；长按 Trigger 0.5 秒，进度圈完成后拿起；松开 Trigger 放回白色归位框 | 实际抓取并归位；RESET 不算完成 |
| 9 起身结束 | 回到 -0.95 / -0.06 | 点击 `STAND UP`，恢复站立与行走 | 坐站转换完成，显示总结 |

中转路线经过西南角 `(-3.10, -1.35)`、西通道 `(-3.10, 1.25)` 和北中转点 `(-0.95, 1.30)`。不引导玩家走进沙发与茶几之间约 0.45 米的缝隙。东侧储物柜目前柜门朝墙，路线没有把它当作可打开柜门的评审点。

观察完成依据是头显朝向在目标方向保持约 1.2 秒，不是眼动追踪，也不代表系统判断了用户的主观感受。用户自己选择 `WORKS WELL`、`CONCERN` 或 `UNSURE`，没有规定正确答案。

## 交互和视觉

- 引导使用白色箭头、脚印圈、眼睛、座椅、手部和归位图标。现有绿、黄、青蓝提示继续使用原来的规则。
- 行走和观察阶段显示紧凑提示；需要评价时才展开按钮。任务提示与目标图标会避让家具，避免被柜体遮住。
- 继续复用现有手柄部位高亮，说明何时用摇杆、扳机或 Grip；没有更改输入动作资产或已有菜单按键。
- 沙发旁的座椅按钮与原沙发批注独立。抓握选择家具仍走原批注流程，扳机点击座椅按钮进入坐姿。
- 坐姿对齐 XR Origin 一次，保留头部和手柄追踪；坐着暂停连续移动和 Snap Turn，同时关闭玩家胶囊。起身先回到安全站位，再同时恢复移动和胶囊。
- 这是可配置的模拟坐姿视点，不应将虚拟沙发视为现实中的座椅。实际身高、舒适度和手臂可触及范围需要头显试用确认。
- 遥控器只允许近手长按 Trigger 抓取；短按只显示提示，不拿起。检测范围为手柄原点周围 10 厘米，白色手形表示已进入可拿取范围，进度圈表示长按进度。Grip 不再负责遥控器拿取。
- Trigger 点击 UI 优先；从 UI 开始的按压须先松开才能拿取遥控器。真正拿起后隐藏该手射线，放下后恢复。重置时仍按住 Trigger 不会自动重抓，追踪丢失会取消抓取。拿着物品时需要先放下再起身。
- 可以关闭、恢复或重播引导。关闭引导后，坐姿的起身和遥控器重置入口仍可用；自由操作不会在后台完成引导任务。重新进入引导时会按当前坐站状态恢复合适的步骤。

## 数据和接入范围

每轮结果保存为 `Application.persistentDataPath/ReviewSessions/living-room-*.json`。版本 2 格式包含 `observations` 点位评价和 `annotations` 物体标注；每条标注保存独立 ID、物体标识/名称/位置、分类、原因、时间和可选点位关联。关闭引导后自由探索产生的标注也保存到本轮，第一次开始路线不会清掉它们。文件通过同目录临时文件替换保存，写入失败会保留草稿，不报告提交成功。此前仅输出到日志的历史标注不会自动回填。

新增的 `ReviewJourney` 是一个独立场景根节点。提示、坐姿锚点和遥控器由它在 Play 时创建在自己的层级内；不会挂入家具子树或改变家具测量包围盒。没有使用旧 `SceneNewBuilder`，也没有重建房间、替换家具或新增全局自动场景入口。

路线是当前已完成客厅的专用点位图。运行时还会用玩家尺度的胶囊检查段落是否可通行；没有可行路线时显示阻挡提示，不画穿过家具的直线。以后改变布局时，需要重新验收点位。

普通桌面预览可以查看路线和提交观察；坐姿及手部抓取需要头显或 XR 模拟器。

## 验证

`route-collision-report.json` 记录了基于当前场景 98 个阻挡体、玩家半径 0.22 米的静态折线检查。运行检查额外使用 0.24 米半径的 Unity 胶囊扫掠。

`validation-report.json` 是隔离 Unity 项目副本中的 Play Mode 检查结果。涵盖完整任务推进、实际物理通路、提示面板无遮挡、坐站重复操作、移动/胶囊恢复、近手抓取、远射线拒绝、重置不冒充完成、JSON 保存、重播、关闭/重启组件及 XR 转桌面恢复。遥控器验证通过合成控制器按键和手部姿态驱动正常 XRI 接触、长按、选择及松手流程；不再手动调用选择事件来代替输入测试。UI 命中优先级另外通过注入命中状态验证。

菜单验证调用实际按钮回调，并等待运行帧检查 X/FREE EXPLORE 持续关闭、GUIDE 重开、HELP 切换、路线隐藏及恢复、已完成观察保留、坐姿与持有遥控器时关闭、完成后重开以及入口/监听器唯一性。生命周期回归在父 HUD 的 OnDisable 回调内关闭 GUIDE，覆盖父节点停用中的清理；另外验证同帧禁用/启用和重配、原三按钮布局及回调恢复。日志持续收集至退出 Play 完成。

`results-validation-report.json` 记录新增结果专项验证：使用真实标注预制体的分类/提交回调，覆盖保存失败回滚及草稿保留、引导前标注保留、点位关联、同物体多原因、提前结束未评价点、双列表及长原因翻页、总结重开与返回补充、坐姿结束/起身、持有遥控器的结束保护、新会话隔离以及总结打开时退出 Play。按钮回调检查不等同于真实头显上的射线命中和点击手感验收。

批处理环境缺少鼠标时，旧版 XR 模拟器 UI 会产生独立异常；验证副本对该 UI 做了无鼠标保护。原项目的模拟器源码没有修改。隔离验证不代替真实头显上的按键、舒适度、视线和手臂范围验收。
