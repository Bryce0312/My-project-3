# 客厅评审引导与坐姿体验

项目入口、成员信息、依赖版本及构建步骤见 [根 README](../../README.md)，目标与当前实现边界见 [项目说明](../../PROJECT_BRIEF.md)。本文件记录客厅专用线路与交互细节；末尾 JSON 记录生成时版本的验证结果，后续变更需重新执行相关检查。

当前 `SceneNew` 已接入完整的一轮评审。打开场景进入 Play，点击 `START REVIEW`。现有基础操作教程可通过 `CONTROLS` 或原有 HELP 再次打开。

右上角 `x` 和 `FREE EXPLORE` 会关闭任务卡、路线及操作高亮，并暂停评审进度。腕部菜单现在是 `PAUSE / HELP / GUIDE / END REVIEW / GAPS`。点击 `GUIDE` 可继续原评审；`HELP` 保留基础操作教程。`END REVIEW` 保存本轮结果并进入双列表总结，结束后该按钮变成 `RESULTS`，关闭总结后可再次打开。

点位评价卡提示用侧面 `GRIP` 指向物体添加分类和原因。分类沿用 `inappropriate size`、`too cramped`、`strange layout`；提交前须选分类并填写原因，最多 500 字符。提交成功后返回原点位，保存失败时保留原输入。

原因输入框提供基础英文屏幕键盘，可用射线和扳机输入字母、空格、退格或清空；`Done` 关闭键盘。该键盘不包含完整中文输入法。腕部 `PAUSE / RESUME` 只控制计时器，暂停引导请使用任务卡的 `x` 或 `FREE EXPLORE`。

总结卡的 `POINT REVIEWS` 列出全部六个评价点，未回答项显示 `UNRATED`。`OBJECT NOTES` 按物体分组列出分类和原因；同一物体的多条标注分别保留，可点击条目并翻页查看完整内容。`RETURN TO REVIEW` 保留数据继续补充，`NEW REVIEW` 新建一轮并保留上一轮文件。坐姿下总结卡内提供 `STAND UP`；拿着遥控器或处于坐站转场时不能结束。有未提交标注时，结束入口会在原编辑卡中提供 `SAVE & END` 与 `KEEP EDITING`，不会静默丢弃草稿。

大总结打开时暂时隐藏 GAPS 间距与家具尺寸提示，关闭后恢复此前状态。两个列表呈现本轮记录；目前没有从旧 JSON 文件导入历史会话的界面。

## 完整线路

| 步骤 | 站位 X / Z（米） | 观察或操作 | 完成条件 |
|---|---|---|---|
| 1 入口整体观察 | -2.45 / -1.55 | 分别观察沙发与电视墙，判断空间是否容易理解 | 到达脚印圈，朝两个眼睛图标观察，然后选择评价 |
| 2 展示柜前方 | -2.85 / 1.35 | 沿西侧通道绕过扶椅，观察储物正面和前方空间 | 观察展示柜后选择评价 |
| 3 书柜与通行 | 1.65 / 1.40 | 经北侧通路，观察书柜及旁边扶椅的关系 | 观察两个目标后选择评价 |
| 4 电视侧向视线 | -0.95 / 1.30 | 从侧面判断电视可见性，之后与坐姿正面视角比较 | 观察电视后选择评价 |
| 5 沙发与茶几 | -1.05 / 0.00 | 从侧面观察桌面高度、沙发前缘和二者间距 | 观察两个目标后选择评价 |
| 6 进入坐姿 | -0.95 / -0.06 | 用扳机点击沙发旁的座椅图标 | 坐姿切换完成 |
| 7 坐姿观察 | 眼位 0 / 1.21 / -0.55 | 正面看电视，再看茶几，判断观看与日常使用关系 | 观察两个目标后选择评价 |
| 8 取放遥控器 | 桌面前缘 -0.20 / 0.445 / 0.14 | 手靠近后出现白色手形；长按 Trigger 0.5 秒，进度圈完成后拿起；松开 Trigger 放回白色归位框 | 实际抓取并归位；RESET 不算完成 |
| 9 起身结束 | 回到 -0.95 / -0.06 | 点击 `STAND UP`，恢复站立与行走 | 坐站转换完成，显示总结 |

中转路线经过西南角 `(-3.10, -1.35)`、西通道 `(-3.10, 1.25)` 和北中转点 `(-0.95, 1.30)`。不引导玩家走进沙发与茶几之间约 0.45 米的缝隙。东侧储物柜目前柜门朝墙，路线没有把它当作可打开柜门的评审点。

观察完成依据是头显朝向在目标方向保持约 1.2 秒，不是眼动追踪，也不代表系统判断了用户的主观感受。用户自己选择 `WORKS WELL`、`CONCERN` 或 `UNSURE`，没有规定正确答案。

## 交互和视觉

- 引导使用白色箭头、脚印圈、眼睛、座椅、手部和归位图标。现有绿、黄、青蓝提示继续使用原来的规则。
- 行走和观察阶段显示紧凑提示；需要评价时才展开按钮。任务提示与目标图标会避让家具，避免被柜体遮住。
- 观察目标图标带视线驱动的呼吸强调：未对准时按 `Time.unscaledTime` 做适度明暗/缩放脉动，视线越对准（点积越高）脉动越收敛，最终稳定高亮。目标世界坐标处另有面向相机的环形十字光环，以及从视线前方指向目标的加粗引导线；引导线末端带箭头，明确指向"看这里"，不再只是一条容易被忽略的细线。任务卡左侧还有一个随目标方位实时旋转的箭头，未对准时追加 `AHEAD / LEFT / RIGHT / UP / DOWN / BEHIND` 文字提示（`BEHIND` 会提示转身），即使目标在视野外也能知道往哪转。目标图标本身改为半透明小准星，避免看起来像一块大标签。光环、引导线与方位箭头都是无碰撞、无射线目标的纯视觉对象，不拦截手柄 UI 或抓取。
- 到位瞬间有一次明确确认：目标图标短促放大提亮、站位圈闪动，并叠加已有手柄震动；`progress` 短暂显示 `Arrived — now observe`。每看完一个目标，图标短暂切换为对勾（XR 与桌面预览都能看到），再进入下一个目标的眼睛图标。
- 从 `FREE EXPLORE`、`HELP` 或坐姿等其他状态切回 `GUIDE` 时，会按当前站位立即重判到位（在脚印圈内直接算到位，不重新等待 0.45 秒），并在当帧重绘路线与目标提示；任务标题、剩余目标数与当前观察目标图标连续显示，已完成观察不丢失。批注 UI 打开时点 `GUIDE` 不会打断当前批注，卡片保持隐藏；关闭批注后恢复 GUIDE 卡片与路线/目标图标，不丢失草稿。
- GUIDE 任务卡跟随右手腕，位于手腕前方约 35 厘米、上方约 19 厘米，并向右侧偏移约 15 厘米，给正前方视线留出空间。前/右方向取 XR Origin 的水平朝向，不随手腕翻转；卡片始终朝向使用者，可用左手射线和扳机点击。过近时保持最小观看距离，遇到障碍时调整位置/大小。右手未追踪、在视线后方或使用普通桌面预览时，卡片回到视野前下方。结束后的大总结卡不采用腕部跟随。
- 头部追踪：真实头显模式下主相机由 `XRHeadPoseFollower` 读取旧版 `InputDevices` 的 `centerEyePosition/Rotation` 直接驱动。`<XRHMD>` 单例动作路径在 Quest Link 下不更新，是"转头时头和场景相对静止"的原因；该组件会停用同相机上失效的 `TrackedPoseDriver`。桌面/模拟器模式会禁用它并恢复 `TrackedPoseDriver`，两种模式各自只有一个相机驱动者。`XRDeviceSimulatorGate` 在检测到真实头显时不会启用键鼠模拟器；若模拟器已先启动，头显出现后会立即关闭，避免它把 HMD 从 Input System 剥离。
- 继续复用现有手柄部位高亮，说明何时用摇杆、扳机或 Grip；没有更改输入动作资产或已有菜单按键。
- 沙发旁的座椅按钮与原沙发批注独立。抓握选择家具仍走原批注流程，扳机点击座椅按钮进入坐姿。
- 坐姿对齐 XR Origin 一次，保留头部和手柄追踪；坐着暂停连续移动和 Snap Turn，同时关闭玩家胶囊。起身先回到安全站位，再同时恢复移动和胶囊。
- 这是可配置的模拟坐姿视点，不应将虚拟沙发视为现实中的座椅。实际身高、舒适度和手臂可触及范围需要头显试用确认。
- 遥控器只允许近手长按 Trigger 抓取；短按只显示提示，不拿起。检测范围为手柄原点周围 10 厘米，白色手形表示已进入可拿取范围，进度圈表示长按进度。Grip 不再负责遥控器拿取。
- Trigger 点击 UI 优先；从 UI 开始的按压须先松开才能拿取遥控器。真正拿起后隐藏该手射线，放下后恢复。重置时仍按住 Trigger 不会自动重抓，追踪丢失会取消抓取。拿着物品时需要先放下再起身。
- 可以关闭、恢复或重播引导。关闭引导后，坐姿的起身和遥控器重置入口仍可用；自由操作不会在后台完成引导任务。重新进入引导时会按当前坐站状态恢复合适的步骤。

## 数据和接入范围

每轮结果保存为 `Application.persistentDataPath/ReviewSessions/living-room-*.json`。版本 2 格式包含 `observations` 点位评价和 `annotations` 物体标注；每条标注保存独立 ID、物体标识/名称/位置、分类、原因、时间和可选点位关联。关闭引导后自由探索产生的标注也保存到本轮，第一次开始路线不会清掉它们。文件通过同目录临时文件替换保存，写入失败会保留草稿，不报告提交成功。此前仅输出到日志的历史标注不会自动回填。

新增的 `ReviewJourney` 是一个独立场景根节点。提示、坐姿锚点和遥控器由它在 Play 时创建在自己的层级内；不会挂入家具子树或改变家具测量包围盒。没有使用旧 `SceneNewBuilder`，也没有重建房间、替换家具或新增全局自动场景入口。

路线是当前已完成客厅的专用点位图。运行时还会用玩家尺度的胶囊检查段落是否可通行；没有可行路线时显示阻挡提示，不画穿过家具的直线。以后改变布局时，需要重新验收点位。

GUIDE 使用 `ReviewRouteGraph` 点位图，不依赖测量模块的 NavMesh。当前场景未保存 NavMesh 数据不妨碍 GUIDE 运行；旧的 NavMesh 测量路线是另一个模块。

普通桌面预览可以查看路线和提交观察；坐姿及手部抓取需要头显或 XR 模拟器。无头显且没有已追踪的 Head 设备时，模拟器门控会等待约 6 秒再启用模拟器；一旦检测到真实头显在追踪，模拟器不会启用（已启动则立即关闭），避免键鼠模拟器把 HMD 从 Input System 剥离。测量系统随后把模拟器作为 XR 输入；如需普通键鼠相机预览，先在编辑器中停用场景的 XR Device Simulator 对象。旧侧边测量面板默认隐藏，不再提供默认可见的模式/输入切换按钮。

## 验证

[`route-collision-report.json`](route-collision-report.json) 记录了验证时场景 98 个阻挡体、检查半径 0.22 米的静态折线检查。GUIDE 运行检查额外使用 0.24 米半径的 Unity 胶囊扫掠。当前 `SceneNew` 对 Rig 的 CharacterController 覆盖值为半径 0.22 米、Skin Width 0.02 米；Rig Prefab 自身默认值为 0.25 米和 0.03 米，不能只读 Prefab 默认值来判断场景中的实际配置。调整布局后需用实际玩家复查。

[`validation-report.json`](validation-report.json) 是隔离 Unity 项目副本中的 Play Mode 检查结果。涵盖完整任务推进、实际物理通路、提示面板无遮挡、坐站重复操作、移动/胶囊恢复、近手抓取、远射线拒绝、重置不冒充完成、JSON 保存、重播、关闭/重启组件及 XR 转桌面恢复。遥控器验证通过合成控制器按键和手部姿态驱动正常 XRI 接触、长按、选择及松手流程；不再手动调用选择事件来代替输入测试。UI 命中优先级另外通过注入命中状态验证。

菜单验证调用实际按钮回调，并等待运行帧检查 X/FREE EXPLORE 持续关闭、GUIDE 重开、HELP 切换、路线隐藏及恢复、已完成观察保留、坐姿与持有遥控器时关闭、完成后重开以及入口/监听器唯一性。生命周期回归在父 HUD 的 OnDisable 回调内关闭 GUIDE，覆盖父节点停用中的清理；另外验证同帧禁用/启用和重配、原三按钮布局及回调恢复。日志持续收集至退出 Play 完成。

新增视觉与恢复需回归：目标图标在视线未对准时脉动、对准时收敛稳定；环形十字光环与引导线出现在目标处且随对准/到位淡出；未对准时任务卡出现正确方位词；到位时图标放大/圈闪/震动与 `Arrived` 提示出现；每看完一个目标短暂显示对勾后再进入下一目标；从 FREE EXPLORE / HELP / 坐姿切回 GUIDE 时，圈内站位直接算到位、路线与目标图标当帧恢复、标题/剩余数/当前目标连续且已完成观察不丢；批注打开时点 GUIDE 不打断批注，关闭批注后恢复卡片与路线/目标图标。所有新增视觉不得拦截手柄射线与家具抓取。本轮为静态自检（脚本语法/字段/事件配对），尚未在隔离 Unity 副本或头显上完成 Play Mode 与真机验收；后续需按上述要点重新执行 `validation-report.json` 对应检查。

[`results-validation-report.json`](results-validation-report.json) 记录结果模块专项验证：使用真实标注预制体的分类/提交回调，覆盖保存失败回滚及草稿保留、引导前标注保留、点位关联、同物体多原因、提前结束未评价点、双列表及长原因翻页、总结重开与返回补充、坐姿结束/起身、持有遥控器的结束保护、新会话隔离以及总结打开时退出 Play。按钮回调检查不覆盖真实头显上的射线命中和点击手感；后续增加的屏幕键盘与腕部位置调整需要单独验证。

批处理环境缺少鼠标时，旧版 XR 模拟器 UI 会产生独立异常；验证副本对该 UI 做了无鼠标保护。原项目的模拟器源码没有修改。隔离验证不代替真实头显上的按键、舒适度、视线和手臂范围验收。
